# Полная выгрузка без докачки, докачка только для записей звонков

Команда `export` каждый раз создаёт новый снимок с нуля и не умеет продолжать после сбоя: упавший снимок помечается файлом `INCOMPLETE`, и выгрузку запускают заново. Команда `recordings`, наоборот, пропускает уже скачанные файлы и при повторном запуске докачивает только недостающие и ошибочные.

Выгрузка разовая, перед переездом, и идёт около 40 минут при лимите 5 запросов в секунду. Временные сбои (429, 5xx, истёкший токен) утилита и так переживает повторами, поэтому полный перезапуск нужен редко, а инкрементальная докачка требовала бы хранить состояние и сверять данные, которые за это время могли измениться. Записи звонков — другое дело: это тысячи файлов и гигабайты с внешнего сервера телефонии, который на часть запросов отвечает ошибкой, так что без докачки их не скачать целиком.

## Consequences

- Если понадобится регулярная выгрузка, например ежедневный бэкап, это решение придётся пересмотреть: не у всех сущностей AlfaCRM есть дата изменения, по которой можно было бы забирать только новое.
