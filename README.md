# alfacrm-export

Полная выгрузка данных AlfaCRM через v2api в SQLite, CSV и XLSX. Нужна для переезда в другую CRM и для просмотра истории обучения: кто, когда и как учился.

Неофициальная утилита, не связана с AlfaCRM. AlfaCRM — торговая марка её правообладателя.

Термины (лид, клиент, группа, урок, посещение, абонемент, оплата, снимок и др.) — в [GLOSSARY.md](GLOSSARY.md). Ключевые решения по устройству утилиты — в [docs/adr/](docs/adr/).

## Установка

Нужен [uv](https://docs.astral.sh/uv/). Все команды запускаются из каталога проекта.

Создайте `.env` в корне проекта (он в `.gitignore`):

```
ALFACRM_HOST=yourschool.s20.online
ALFACRM_EMAIL=почта_пользователя_CRM
ALFACRM_API_KEY=ключ_v2api
```

Ключ API берётся в AlfaCRM: «Мой профиль» → «Ключ API». У роли этого пользователя должен быть доступ к API. Те же переменные можно задать в окружении — они важнее `.env`.

## Команды

```
uv run alfacrm-export export        # полная выгрузка в новый снимок data/<дата-время>/ (~30 мин)
uv run alfacrm-export recordings    # скачать записи звонков в последний снимок (можно перезапускать)
uv run alfacrm-export output        # пересобрать csv/ и report.xlsx из SQLite последнего снимка
uv run alfacrm-export --help
```

Опции:

- `export --branch N` — id филиала. По умолчанию первый активный.
- `export --rps 4` — запросов в секунду. Лимит AlfaCRM — 5 на все методы.
- `recordings ПУТЬ_К_СНИМКУ --workers 8`, `output ПУТЬ_К_СНИМКУ` — работать с конкретным снимком, а не с последним.
- `--data КАТАЛОГ` (перед командой) — где лежат снимки. По умолчанию `data`.

Если `export` упал, в каталоге снимка остаётся файл `INCOMPLETE`. Такой снимок неполный: запустите `export` заново. Ошибки 429 и 5xx и истёкший токен утилита обрабатывает сама.

## Что в снимке

```
data/2025-01-31_120000/
├── alfacrm.sqlite      # всё: главный результат
├── csv/<таблица>.csv   # по файлу на каждую таблицу SQLite, без raw_json
├── report.xlsx         # отчёт для человека
└── recordings/         # mp3 звонков (после команды recordings; не в git)
```

### SQLite

На каждую сущность AlfaCRM — своя таблица:

- одна колонка на каждое поле API;
- списки и вложенные объекты лежат в колонке как JSON;
- `raw_json` — запись ровно в том виде, в каком её вернул API.

Поле-список id (например `teacher_ids`, `group_ids`, `customer_ids`) дополнительно разложено в таблицу связей `<таблица>__<поле>` с колонками `<таблица>_id` и `value`. Пример: `lesson__teacher_ids(lesson_id, value)`.

| Таблица | Что это |
|---|---|
| `customer` | Лиды (`is_study=0`) и клиенты (`is_study=1`), включая удалённых (`_removed=1`) |
| `groups` | Группы, включая удалённые (`_removed=1`) |
| `cgi` | Состав групп: кто с какой даты по какую был в группе |
| `lesson` | Уроки всех статусов: 1 — запланирован, 2 — отменён, 3 — проведён |
| `lesson_detail` | Посещения: клиент × урок, `is_attend`, причина пропуска, оценка, `ctt_id` — абонемент |
| `customer_tariff` | Абонементы (в том числе у лидов на пробных занятиях); `tariff_id` → `tariff` |
| `pay` | Оплаты и списания |
| `communication` | Комментарии к лидам и клиентам (`related_id` → `customer.id`) |
| `task` | Задачи |
| `phone_call`, `sms_message`, `mail_message` | Звонки (`record_url` — ссылка на запись), SMS, письма с HTML |
| `recording` | Результат скачивания записей: `phone_call_id`, путь к файлу, статус (`ok` / `empty` / `error: …`) |
| `log` | Журнал изменений CRM (кто, что и когда менял) |
| `user`, `teacher` | Сотрудники и педагоги |
| справочники | `subject`, `tariff`, `room`, `location`, `study_status`, `lead_status`, `lead_source`, `lead_reject`, `customer_reject`, `discount`, `lesson_type`, `pay_type`, `pay_account`, `pay_item`, `pipeline`, `branch` |
| `_meta` | Когда, откуда и сколькими запросами сделан снимок |

Пример запроса — история обучения одного клиента:

```sql
SELECT l.date, l.status, d.is_attend, d.reason_name, s.name AS subject
FROM lesson_detail d
JOIN lesson l ON l.id = d.lesson_id
LEFT JOIN subject s ON s.id = l.subject_id
WHERE d.customer_id = 123
ORDER BY l.date;
```

### report.xlsx

- **Клиенты** — все, кто учился, платил или был в группе: статус, источник, первый и последний урок, посещено и пропущено, сумма оплат, баланс.
- **Посещения** — строка на каждое посещение: дата, время, клиент, группа, предмет, педагог, был или нет, причина, оценка, абонемент.
- **Оплаты** — дата, клиент, сумма, касса, статья.
- **Группы** — кто и в какие даты состоял в группе.

Новый лист добавляется парой «название → SQL» в `REPORT` в `src/alfacrm_export/output.py`. Затем запустите `uv run alfacrm-export output`.

## Чего нет в выгрузке

API AlfaCRM не отдаёт:

- файлы и вложения;
- названия дополнительных полей — они выгружаются как колонки `custom_*` с кодом поля;
- справочники статусов и уровней групп — в таблице `groups` есть только `status_id` и `level_id`.

Записи звонков хранятся у провайдера телефонии, AlfaCRM отдаёт только ссылки (`record_url`). У некоторых провайдеров записи скачиваются по ссылке без авторизации. Ссылки могут перестать работать после закрытия аккаунта, поэтому их стоит скачать командой `recordings`.

## Особенности API, которые учитывает утилита

- Без фильтра `removed=1` API молча не отдаёт удалённых лидов, клиентов и группы.
- Без фильтра `status` API отдаёт только проведённые уроки.
- Выгружается один филиал: по умолчанию первый активный, другой можно выбрать через `--branch`.
