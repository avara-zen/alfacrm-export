# SQLite с исходным JSON как главный результат выгрузки

Главный результат снимка — файл `alfacrm.sqlite`, а не CSV. В нём на каждую сущность AlfaCRM своя таблица: колонка на каждое поле API, колонка `raw_json` с записью ровно в том виде, в каком её вернул API, и отдельные таблицы связей для списков id (`<таблица>__<поле>`). CSV и `report.xlsx` строятся из базы и пересобираются командой `output` без обращения к API.

Так решили, потому что выгрузка нужна для двух вещей: импорта в другую CRM и отчётов «кто, когда и как учился». Обе требуют связей между уроками, посещениями, группами, абонементами и оплатами. По плоским файлам их пришлось бы собирать вручную, а в SQLite это обычные `JOIN`. `raw_json` дублирует колонки ради страховки: если раскладка по колонкам что-то потеряла или исказила, исходные данные остаются, а API после закрытия аккаунта уже не спросить.

## Considered Options

- **CSV или JSONL напрямую, без базы.** Проще, но связи и отчёты пришлось бы собирать вне утилиты.
- **Только нормализованные колонки, без `raw_json`.** База вдвое меньше, но любая ошибка раскладки становится необратимой потерей данных.

## Consequences

- `raw_json` не попадает в CSV, иначе CSV удваивался бы в размере.
- Схема таблиц выводится из ответов API, а не задаётся в коде: новое поле в AlfaCRM само становится колонкой, а поле, которого нет ни в одной записи, не появится вовсе.
